## 七、跨场景联动（DEFAULT_LINKS）

```js
const DEFAULT_LINKS = [
  { from:"office", kw:"交付", to:"study", taskTitle:"奖励：看一集技术分享视频" },
  { from:"study",  kw:"复习", to:"code",  taskTitle:"奖励：写个有趣的小项目 30 分钟" },
  { from:"code",   kw:"上线", to:"life",  taskTitle:"犒劳：吃顿好的 / 看部想看的片" }
];
```

**问题**：
- 只有 3 条默认规则，**设置 → 场景联动** 是入口，但用户能添加的规则数 / 触发时机不清楚
- kw 关键词匹配过于朴素——只查标题包含字符串，**没有正则 / 标签 / 状态触发**
- 触发后**直接生成任务**，没有"延迟 N 天"、"先提醒"等选项
- 缺"反向链路"——任务完成后**不**通知源场景

## 总结

**现状**：
- 6 场景 28 个功能卡（不含 6 概览）
- **每个卡只有 CRUD**（添加/查看/删除）——"分析"和"联动"几乎为 0
- **跨场景联动 3 条**——DEFAULT_LINKS 是占位
- **统计/进度/汇总**只在少数卡有（健康/学习/办公概览）——多数卡没 sum

**根本问题**：
- 卡的字段是"原子数据"（每条记录独立的字段）
- 缺"**视图**"层——把多条记录"折叠"成单个洞察（项目进度、缴费总额、出勤率、阅读量、错题率）
- 缺"**触发器**"层——一条记录变更时，跨场景自动反应

**建议下轮工作方向**：
1. 优先做"视图"层（让用户先看到"我这一周做了什么"）——工作量大但直观
2. 再做"触发器"层（让数据有联动）——技术复杂
3. 12-14 号候选（汇总/关联/收藏源）性价比高，2-3 个工作日内可完成

具体做什么等你定。

# v2 报告：场景驱动分析（白领工作日 × 6 场景功能卡）

> 视角：不再"字段补缺"维度——而是**真实用户在哪一时刻打开哪个卡、要看到什么、要做什么**。
> 调研：3 类白领（产品经理 / 软件工程师 / 行政主管）× 5 个时间点（早/午/下午/下晚/月末）× 6 大场景 = 90 个真实使用场景。
> 结论：v1 列的 14 条候选**部分过度设计**（白领不会用到的功能）、**部分仍然不够**（卡住了白领真实痛点）。

## 1. 真实使用矩阵（精选高频场景）

## 2. 逐场景按"是否白领高频"重新评估

### 办公 office（白领工作主战场）

**会议 meeting**——白领最痛点是"会议结论→任务落地"
- v1 建议"加行动项追踪闭环"
- v2 评估：**直接覆盖**：结论文本里识别"@姓名 + 截止"自动生成任务（**会议行结论→任务**一键落地）
- **不**做：单独的"行动项表/状态/负责人字段"——白领会议是"快速记下→自动派活"，**不愿多填字段**
- 操作：会议笔记末尾加 [📌 一键转任务] 按钮（已存在"→ 生成任务"——v2 评估**改用正则识别 @人+日期 派发**而非纯文本）

**项目 project**——白领痛点是"项目进度可视化"
- v1 建议"加子任务关联 + 进度条"
- v2 评估：**保留子任务（已有 task.sc/priority）但升级为"项目视图"**——按项目分组显示所有 task，进度=done/(done+open) 自动算
- 不做：project 单独存名/状态——**让 task 自带 sc="office"+"project=xxx" 标签**，project 表只存展示元信息
- 操作：项目 tab 加"项目视图"（按项目聚合任务）

**报销 expense**——白领痛点是"金额/分类一目了然"
- v1 建议"加金额合计 + 分类统计"
- v2 评估：**仅做 sum 区域**——已经缺"本月总额/按分类聚合"两行；不要碰字段

**考勤 attendance**——白领痛点是"月度出勤率"
- v1 建议"细分 + 月度统计"
- v2 评估：**白领考勤通常公司 HR 系统管，本应用不是 HR 工具——不细化**；但加 sum 行"当月出勤天数"有用

**结论 office 4 卡改动优先级**：会议自动派活 > 项目视图 > 报销 sum > 考勤 sum

### 学习 study（白领充电场景）

**知识库 knowledge**——v1 无建议，v2 评估：白领的"知识库"实际是"读书笔记/网课笔记/会议复盘"，**目前结构已 OK**，只加 "标签筛选" 增强

**阅读 reading**——v1 建议"加进度/页数"
- v2 评估：**白领阅读很少在桌面工具记进度**——通常用 Kindle/微信读书。**降级**：去掉此功能（不建议加 page/total 字段）

**练习 exercise**——v2 评估：**已经做了 SM-2 错题入复习**（v3.2 阶段二），不增

**考试 exam**——v2 评估：**白领不常用此卡**——保持现状

**结论 study 改动优先级**：知识库标签筛选（小修）> 其余不动

### 数据 data（白领分析场景）

**报表 report**——v1 建议"加指标快照标准格式"
- v2 评估：**白领的实际需求是"这个月项目 X 的成本"**——报表不需要"快照格式"，需要"多源聚合视图"
- **降级**：不强求报告卡升级。**新增"数据视图"卡到概览顶部**（白领高频：看到项目数/任务数/金额/出勤 4 块卡片）

**图表 chart**——v1 建议"图表绑定数据自动刷新"
- v2 评估：**图表商店里的图表是"模板"**——不绑定数据是设计选择，不强改

**SQL sql**——v2 评估：白领用 SQL 卡的频率**很低**（非技术岗位不查 SQL）——保持现状

**结论 data 改动**：**只在概览加 4 块"今日工作总览"卡片**（跨场景汇总）—— 1 处改动覆盖 6 场景需求

### 设计 design（白领创意场景——非主战场）

**CAD/image/UI/3D**——v1 建议"作品集"
- v2 评估：**白领非设计师**，本应用对大多数白领用户是"占位卡"。**降级**：不强行做作品集。
- **保留 v3.2 阶段四的图片附件**（已加 IDB blob 存储）——白领偶尔用得到

**结论 design 改动**：图片附件已加，本次不动

### 编程 code（白领主场景之二——开发者）

**运行器 runner**——✅ v3.2 阶段一已加运行历史，**降级**：不再加更多功能

**正则 regex / 前端 frontend**——v2 评估：白领开发者用这两张卡频率**极低**（多数用 IDE 调试），**保持现状**

**SQL sql 复用**——v2 评估：开发者用 SQL 卡**仅在调试复杂报表时**，保持现状

**结论 code 改动**：全部不动（v3.2 阶段一已覆盖主要痛点）

### 生活 life（白领个人场景——高频）

**计划 plan**——v1 评估"OK"
- v2 评估：**白领痛点是"日计划"**（不是周计划/月计划）。当前字段 OK，但**缺的机制是"日复盘"**——一周结束应能自动汇总"完成/未完成/拖延"

**健康 health**——✅ v3.2 阶段二已收敛双轨，**保持**

**缴费 bill**——v1 建议"提前 X 天提醒"
- v2 评估：**白领痛点是"我下周要交什么"**——不是"提前 X 天通知"，是"缴费日历"。**改方案**：在概览/侧栏加"本周缴费"列表（按 due 排序，已缴的折叠），**不**做 push 通知（白领不想被打扰）

**采购 shop**——v2 评估：白领采购频率低，**保持**

**结论 life 改动**：缴费改"日历列表"（不推送）> 其余不动
