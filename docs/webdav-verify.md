## 冲突路径（可选，双开验证）

两台设备（或两个桌面实例）都配置同一 WebDAV：
- A 上传快照后，B **不改内容直接上传** → B 会看到「云端版本已被其他设备修改（上传被拒）」的确认弹窗 ——
  这是 **ETag 冲突检测**（412）在起作用：**不静默覆盖**。选「用云端覆盖本机」即拉回 A 的版本。

## 已知边界（如实）

- 浏览器形态发不出 WebDAV 请求（服务不回 CORS 头）——这是服务端行为，桌面版不受影响；
- 本版是**手动**同步（点按钮才发生），没有自动/定时同步；自动节奏等 WebDAV 验收通过后再排；
- 密码只存本机（设备密钥加密），换设备需重新配置——这是「密钥不出本机」的设计，不是缺陷。
  **【后注 2026-10-16 · v3.7.128】** 上面这句在写下时**并不成立**：WebDAV 三个键漏出了云快照

### 两个环境坑（比结果更值钱， anyone 在本机跑 Electron 探针都会踩）

1. **`ELECTRON_RUN_AS_NODE=1` 会让 Electron 起不来**，症状极难认：进程秒退 `exit 9`，报
   `electron.exe: bad option: --remote-debugging-port=...`（这是 **Node** CLI 解析器的口吻，
   不是 Electron 的），CDP 端口永不就绪。排查中先后误判过 MSYS node、`.cmd` 启动器、
   二进制平台不匹配，都排除了——最后揪出这个环境变量来自宿主进程，一路继承下来。
   **解**：spawn Electron 时显式 `delete env.ELECTRON_RUN_AS_NODE`。
2. **受保护环境里 `rmSync(recursive)` 常被删除守卫拦**（本机 100% 复现，报错还很唬人）。
   **解**：同盘 `renameSync` 改名挪走即可，顺带把旧 profile 留在 `_probe/.trash-wd-udata-<ts>`
   里给事后翻真相（Electron 日志就在其中）。

这两条已作为**自愈补丁**写进探针：环境变体自愈 + stderr 转储（原 `stdio:"ignore"` 把 Electron
的临终输出吞得干干净净，这是本次能误导一小时的直接原因）。CDP 起不来时会打印进程退出码与
stderr 原文，不再丢一句「端口没起来」让人猜。

> 跑法：`npm run src:inject` → `WD_ROOT=<隔离副本> node _probe/webdav-ui-accept.mjs` →
> `npm run src:extract`。给不给 `WD_PASS` 决定跑完整 8 步还是本节的错凭据演练。

### 缺陷 1（安全）：云快照把 WebDAV 凭据带上了云

跑完 8 步后把云端快照文件直连拉下来看，`wb_agent_webdav_pass`（设备密钥密封的密码**密文**）、
`wb_agent_webdav_cfg`（含**明文**账号邮箱）、`wb_agent_webdav_meta`（本机同步元数据）三个键
**都在里面** —— 与本文档 §已知边界 写的「密钥不出本机」**直接冲突**。

根因：`src/render-overview.js` 的 `SYNC_EXCLUDED_KEYS` 在 v3.7.94 立下「用设备密钥密封的凭据
不上云（上云无跨端收益、纯增后端暴露面）」原则，据此排除了 `wb_access_token` /
`wb_integration_api_keys` / `__dk` 等，但 v3.7.120 引入 WebDAV 时**新增的三个键漏了**。
修法：三个键补进清单（入站侧 `_applyCloudSnapshot` 用同一份清单对称过滤，无需另改）。

**修复的真机复验（2026-10-16 复跑）**：同一账号、同一条 8 步流程再跑一遍，把云端快照拉下来 ——
键数 **15 → 12**，三个键**全部消失**，业务键（`tasks` / `theme` / `onboarded` 等）**照常在**
（证明排除没做成误伤）。

### 缺陷 2（可用性）：坚果云根目录不可写，而默认地址恰好就是根目录

本机实测三组，结论明确：

| 操作 | 结果 |
|---|---|
| `PUT /dav/x.json`（**根目录**） | **404** |
| `MKCOL /dav/sub/` | 201 |
| `PUT /dav/sub/x.json` | 201 |

**坚果云 WebDAV 根目录不允许直接放文件，必须先建子目录。** 而默认 `WD_URL` 恰好就是这个根目录 ——
用户照默认值填 → 点上传必然 404；原提示只说「上传失败（HTTP 404）」，用户无从下手。
修法：`webdavPut` 带回状态码，404 单独给一条带「子文件夹」指引的双语文案。

修复后真机复验，默认根目录下提示已如实上屏：

```
上传失败：目标路径不存在（404）—— 请确认地址里的文件夹已在服务端建好。
注意坚果云等服务的根目录不允许直接放文件，必须指定一个已存在的子文件夹。
```

> **给用坚果云的人两条实操提示**：① `WD_URL` 要填到**已存在的子文件夹**（如
> `https://dav.jianguoyun.com/dav/我的坚果云`），别用根目录；② 坚果云对 **WebDAV 删除目录**
> 回 403 —— 用 MKCOL 建出来的空目录**删不掉**，只能去客户端/网页端手工删（文件可以正常 DELETE）。

### 顺带修掉的探针自身缺陷

探针此前**从未在本机成功跑过**。跑通的过程里修掉它自己四个问题（**都不是产品缺陷**）：
Playwright 默认 dismiss 原生 `confirm`（表现为「点了清除本机键还在」）、toast 等 7 秒再抓早已消失
（表现为「失败却看不到提示」的假静默）、`rmSync` 被删除守卫拦（改同盘改名）、
「服务端键数 == 本机快照键数」断言过紧（应用运行期本就会长键，改为 `≥`）。
