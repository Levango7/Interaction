**这次验收当场抓到一个真 bug（v3.7.120 已修）**：坚果云的 **PUT 成功响应不回 ETag 头**
（只有 GET 回），而 `electron/main.js` 把 PUT 响应头的 etag 交渲染层存进 `wd_meta` → 空 →

「云端被其他设备修改」）。现为「PUT 2xx 且无 etag 时补一次同路径 GET 取权威值」。

下面 8 步里的 UI 段已做成一条命令：`_probe/webdav-ui-accept.mjs`（本地探针，不入库）。
它起**真 Electron**（独立 `--user-data-dir`，不碰你正式安装的 profile），按顺序点

`webdav_meta.etag` 非空（v3.7.120 那条 bug 的回归点）、清除后**远端文件仍在**、`app.log` 里不含凭据。


## 验收步骤（逐项勾）

| # | 动作 | 预期 |
|---|---|---|
| 1 | 点 **测试连接** | 状态行显示「连接成功（应用密码有效）」；失败则显示具体原因（401=密码错） |
| 2 | 点 **上传快照** | toast「已上传快照（N 键）」；坚果云网页端 `我的坚果云` 根目录出现 `agent-workshop-snapshot.json` |
| 3 | 再点一次 **上传快照** | 仍成功（这次带 If-Match 续传，坚果云上文件内容更新、旧版本可在坚果云回收站看到） |
| 4 | 改一条任务（如勾选完成）→ 再 **上传快照** | 上传成功且新内容包含该改动（网页端打开 json 核对） |
| 5 | 点 **用云端覆盖本机** | 先弹确认「只覆盖云端包含的键，本机独有键不动」→ 确认后 toast「已应用云端快照」 |
| 6 | 清掉本机一条任务 → **用云端覆盖本机** | 该任务被云端版本恢复（数据回来了） |
| 7 | 浏览器形态打开同一页面 | WebDAV 段显示「仅桌面版」说明、**没有**测试连接/上传按钮（诚实门控） |
| 8 | 集成页点 **清除** | 配置与密码抹净；云端文件不受影响 |

## 冲突路径（可选，双开验证）

两台设备（或两个桌面实例）都配置同一 WebDAV：
- A 上传快照后，B **不改内容直接上传** → B 会看到「云端版本已被其他设备修改（上传被拒）」的确认弹窗 ——
  这是 **ETag 冲突检测**（412）在起作用：**不静默覆盖**。选「用云端覆盖本机」即拉回 A 的版本。

## 已知边界（如实）

- 浏览器形态发不出 WebDAV 请求（服务不回 CORS 头）——这是服务端行为，桌面版不受影响；
- 本版是**手动**同步（点按钮才发生），没有自动/定时同步；自动节奏等 WebDAV 验收通过后再排；
- 密码只存本机（设备密钥加密），换设备需重新配置——这是「密钥不出本机」的设计，不是缺陷。
