## OD-004 缺陷详述

**现象**：`Ctrl+K` → 搜「清空」→「清空全部数据」→ 确认「此操作不可恢复」→ 900ms 后页面刷新，
**示例任务（提交本周周报 / 修复登录页 500 报错 / 复习分布式事务 / 缴水电费）又回来了**。

**证据**：

- `src/ui-backup-stats.js:251-256`：`allKeys().forEach(k => localStorage.removeItem(k))` → 含 `wb_agent_init`；
  toast 用 `msg.clearedReload` = 「已清空，页面将重新载入示例」。
- `src/data-migrate.js:278-280`：`if(load(PREFIX+"init", false) || localStorage.getItem(PREFIX+"tasks") !== null) return;`
  —— 清空后两个条件都不成立 ⇒ `seed()` 落种。

**严重度**：P2（不影响数据安全；但命令名与行为相反，且"从零开始"无路径）。

**为什么当时没擅自改**：甲案（只改文案）与乙案（改行为）结论相反，属产品口径；该批是走查批次，
改行为等于替用户做决定。**2026-10-18 用户裁「乙 吧」⇒ 已按乙案落地并销账**（见上表 Resolution）。

## OD-002 缺陷详述

**现象**：登录弹窗切到微信扫码 → 显示一张写着「微信登录（演示）/ 未配置微信 appid / scene: wx_xxx」的 SVG，
下方提示「打开微信「扫一扫」完成登录」→ 客户端每 2.5s 轮询 `/wechat/status` → **永远 pending**，
5 分钟后报「二维码已过期，请关闭后重新扫码」。用户视角：功能看起来能用，实际是死循环。

**证据**：
- `server/src/auth.js:313` `return ok(res, { qr: ..., scene, expireIn, demo: true });`
- `server/src/auth.js:307-309` 注释：「演示码必须让调用方消费端看得出是演示（demo:true），不能伪装成真二维码」
- `src/render-overview.js:1190-1196` 只判 `if(qr)`，`d.demo` **未被读取**

**严重度**：P1（非安全缺陷——无认证绕过；但为用户可见的功能不可用 + 误导性文案）。
