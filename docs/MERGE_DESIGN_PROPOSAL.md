## 1. 执行摘要

### 核心发现

| 维度 | 结论 |
|------|------|
| **HTML 结构** | 两版本 **几乎完全一致**（差异 < 2%） |
| **JS 逻辑层** | 旧版是当前版的 **3 倍代码量**（73K vs 24K 行） |
| **当前版优势** | 架构清晰、模块规范、错误处理完善、无障碍(a11y)完整 |
| **旧版优势** | 功能更丰富（可能有被裁剪的业务逻辑）、AI 对话循环更完整 |
| **合并策略** | 以当前版为骨架，从旧版中挖掘丢失的功能逻辑，选择性回填 |

### 一句话结论

> **当前版本的"空壳"判断不完全准确**——HTML/UI 层面功能完整，主要差距在 JS 业务逻辑层。建议以 v1.15.0 为基底，从 .bak2 中提取丢失的逻辑函数进行靶向回填。

## 12. 合并实施路线图

### Phase 1: 差异审计 (预计 2-3 小时)

```
□ 步骤 1.1: 提取旧版所有函数名列表 (grep "function ")
□ 步骤 1.2: 与当前版函数名列表做差集 → 找出"旧版有但当前版没有"的函数
□ 步骤 1.3: 逐一审查差集函数，分类为:
   → A) 有价值需回填的功能逻辑
   → B) 已被重构/合并到其他函数的（无需回填）
   → C) 死代码/废弃功能（不回填）
□ 步骤 1.4: 对 A 类函数做依赖分析（调用了哪些工具函数、依赖哪些数据结构）
```

### Phase 2: 靶向回填 (预计 3-5 小时)

```
□ 步骤 2.1: 回填 AI 对话相关的高价值函数（H1-H5）
□ 步骤 2.2: 适配 DOM 助手函数名 ($$ → $)
□ 步骤 2.3: 适配存储读写接口 (load/save → 当前版封装)
□ 步骤 2.4: 单元测试验证回填功能（如有测试框架）
□ 步骤 2.5: 手动冒烟测试 AI 对话全流程
```

### Phase 3: 清理收尾 (预计 1-2 小时)

```
□ 步骤 3.1: 删除临时文件 (recover*.js/ps1, debug*.js, .corrupt-snapshot)
□ 步骤 3.2: 清理当前版中的 no-op 空函数残留 (R1)
□ 步骤 3.3: 版本号升级至 v1.16.0 (或 v2.0.0 表示大合并)
□ 步骤 3.4: 更新 BUILD_TAG
□ 步骤 3.5: Git commit + tag
```
