# 半成品功能完善路线图（v1.11.2 起）

> 依据：2026-08-16 对 agent-workbench.html 36,213 行的逐块接线勘察（11 个 v1.8-C/D/E/F 功能块）+《项目全景审查报告》表 4-4。
> 结论修正：审查报告把 11 块一律判"模拟/框架级"过粗。实测块 1/6/8 已有相当比例真实浏览器 API 调用，
> 块 4/5 网络层真实（真 fetch、真端点），纯 mock 的只有块 2（网络层）、9（引擎层）、10、11 四块。
> **所有块的共同短板是事件源与 UI 入口缺失**（除块 1、8 外均无 UI 入口，除块 1 外均零测试覆盖）。

## 总体策略：三档处置

| 档 | 判据 | 块 |
|---|---|---|
| A 转正接线 | 引擎/协议层已真实，只差事件源或入口 | 1 自动化、5 OAuth2、6 Webhook 总线、8 语音、11 生物识别 |
| B 补面板 | 请求层真实，缺 UI 与数据回写 | 4 九大集成、7 工作流画布、9 多模态 |
| C 按需立项 | 需服务端/原生工程链，单文件内无解 | 2 CRDT 协作、3 企业 SSO、10 Capacitor |

原则：**先接事件源（让已有引擎转起来），再补 UI 入口（让人用得上），最后补外部依赖**。
每步转正必须同时补定向测试（当前 11 块零覆盖是最大风险）。

## 第 0 期（v1.11.2 本次实施）

### 0.1 L4 Webhook SSRF 校验补码（认证校验）✅ 已完成

- 发现比报告更深一层：WHATWG URL 会把数值形主机**自动规范化**（`https://2130706433/` → hostname `127.0.0.1`），真正的逃逸通道是撞 dev 白名单而非绕过正则。
- 策略：回环目标（localhost / 127/8 / [::1]，含一切数值形伪装与序列化后的 `::ffff:` 映射）**仅允许 http**（本地开发场景），https 回环一律拒绝；新增 inet_aton 兼容解析器 + IPv6 展开 + 统一黑名单（含 CGNAT 100.64/10、组播 ≥224）。
- 回归：`tests/l4-webhook-ssrf.test.js` 36 用例（28 拦截 + 8 放行不误杀）。
- 已知残留：DNS rebinding（需解析后校验，浏览器 fetch 无注入点），文档化接受。

### 0.2 任务事件源接线（激活块 1 规则引擎 + 块 6 Webhook 总线）

**现状**：规则引擎/cron/webhook 出站全真、自动化弹窗 UI 完整，但 `evaluateTriggers` 只被 `handleWebhookEvent` 调用——任务完成/创建**从不触发规则**，规则引擎是"聋"的；`webhookEmit` 全文件零调用，HMAC/DLQ/重试引擎空转。

**设计**：
1. 新增 `_emitTaskEvent(type, task)` 统一分发器（放在 completeTask 旁）：构造 `{type, scenario, task, ts}`（task 深拷贝防后续突变）→ 并行喂 `evaluateTriggers(ev)`（自动化规则）与 `webhookEmit(type, payload)`（订阅总线），两者各自 try/catch + pushDiag，互不阻塞业务写入。
2. **防重入护栏** `_automationEvaluating`：规则动作/场景联动再写任务时不再次分发（防 A 完成 → 规则创建 B → B 又触发规则的循环）。规则动作想显式链式触发时未来可加 `bypassGuard` 选项。
3. 挂接点（第一期仅 task_complete——UI 表单的默认触发类型）：`completeTask()` 内 `runLinks(t)` 之后。task_create/task_delete 挂接（表单提交 + execTool create_task/delete_task + 回收站清空）排第 1 期。
4. 事件类型词表沿用现有 UI 选项：`task_complete` / `task_create`（+ 后续 `task_delete`）。

**测试**：`tests/automation-emit.test.js`——① 建规则（trigger task_complete → 动作 create_task），completeTask 后断言动作任务已创建；② 规则动作产生的任务不再次触发（防重入）；③ webhookRegister 订阅 + mock httpClient，completeTask 后断言 delivery history 有记录。

**风险评审**：completeTask 是核心热路径——分发器全 try/catch、异常只进 diag 不上抛；规则数量小（用户手建），性能影响可忽略；jsdom 下 evaluateTriggers/webhookEmit 为函数声明提升，加载顺序无碍。通过。

### 0.3 生物识别 WebAuthn 实现（认证校验补码，块 11 转正核心）

**现状**：状态机/会话/重试/受保护动作全真，但 `biometricSetAuthImpl` 无人注入，`biometricAuthenticate` 恒 `not_available`；全文件无任何 WebAuthn。

**设计**：写 `_webauthnBioImpl(opts)` 单函数实现（契约：`opts.action ∈ check/register/authenticate`，返回 `{result, type, availability?, error?}`）：
- `check`：`PublicKeyCredential.isUserVerifyingPlatformAuthenticatorAvailable()` → available / hardware_missing / not_supported；
- `register`：`navigator.credentials.create`（platform 认证器 + userVerification required，challenge 用 crypto.getRandomValues 32B，alg -7/-257），NotAllowedError → cancelled；
- `authenticate`：`navigator.credentials.get`（rpId 取 location.hostname）；
- 脚本加载时自动注入 `biometricSetAuthImpl(_webauthnBioImpl)`——不改变"无 WebAuthn 环境 → not_available"的既有语义，只让支持的浏览器（Chrome/Edge + Windows Hello / Touch ID）真正可用。
- v1 简化：不持久化 credential id（get 不带 allowCredentials，由平台认证器选择），type 统一报 fingerprint（平台认证器种类浏览器不区分）——第 1 期若做"敏感操作门禁"再存 id。

**测试**：`tests/biometric-webauthn.test.js`——① 无 WebAuthn（jsdom 默认）→ check 返回 not_supported、authenticate 返回 not_available；② 注入 mock `navigator.credentials` + `PublicKeyCredential.isUserVerifyingPlatformAuthenticatorAvailable` → check available；③ mock `credentials.get` resolve → biometricAuthenticate result=success；NotAllowedError → cancelled。

**风险评审**：零依赖、纯标准 API；失败路径全覆盖（unsupported/cancelled/error 三态映射到既有状态机）。通过。

### 0.4 OAuth2 回调闭环（认证校验补码，块 5 断头处接通）

**现状**：PKCE（真 crypto）/exchange/refresh/revoke/state 一次性防 CSRF 全真，但 `oauth2BuildAuthUrl` 只返回 URL 不跳转，页面加载也不解析 `?code=`——流程两头都断。

**设计**：新增 `_oauth2HandleCallback()`（启动时调用，fire-and-forget）：
1. `location.search` 含 `code`+`state` 才处理（error= 也处理为失败 toast）；否则直接返回，零开销。
2. `oauth2ValidateState(state)` 一次性取出 `{provider, pkceVerifier}`（内部已防重放）——state 非本应用发起则忽略并清 URL。
3. `oauth2ExchangeCode(provider, code, {codeVerifier, redirectUri: location.origin+pathname})` 走真 fetch 换 token → `oauth2StoreToken` 落盘。
4. 结束后 `history.replaceState` 清 query（防刷新重复处理），成功/失败 toast。

**测试**：`tests/oauth2-callback.test.js`——预置 provider + state 到 `wb_oauth2_*` 键、`history.replaceState` 注入 `?code&state`、stub fetch 返回 token → 断言 token 落盘、URL 已清理；state 不匹配 → 不发请求。

**风险评审**：仅在显式带 code 参数时激活（正常启动零路径）；token 明文存 localStorage 是既有现状（模块注释自认），维持并在路线图第 1 期接 Electron safeStorage。通过。
