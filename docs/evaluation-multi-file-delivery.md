## 二、提议的收益逐条核

| 候选收益 | 核验结论 |
|---|---|
| **缓存粒度**（只重下文变块） | 真实但量级小：今天每次发版 SW 重下 ~3MB 单文件；多文件后按块差分。但本应用生产形态是自建/单人本地优先，用户基数与更新频率都低，SW toast+刷新已把更新体验解决。省的是「发版日的一次 3MB 下载」。 |
| **首屏速度** | 边际：SW 热身之后全部本地命中、无网络瀑布；3MB 内联解析在当代机器是百毫秒级。没有「瀑布阻塞」可解（脚本本来就要全量执行）。 |
| **CSP 收紧**（script-src 去 `unsafe-inline`） | **唯一硬收益**，见 §四——但短期拿不干净，且要连内联事件属性一起清才是真收紧。 |
| **调试/堆栈** | 小：开发期 `src/` 已分文件；生产内联丢映射。已有 source 态工具链缓解。 |

## 三、成本逐条核（都是实的）

1. **构建链分支**：`build.mjs` 需增 multi 模式（复用 `src-split.mjs` 的块清单——注入与外置本质是同一条替换管的两个方向，这部分顺手）；但 **`build:check` 五源门禁与 `release.mjs` 五源 bump 都不覆盖第二产物**，要么扩源（版本一致性面从 5 → 6+），要么 multi 产物游离在版本门禁外——后者正是本仓花了三个版本才焊死的「多源漂移」事故形态（v3.7.40 误提交、撞号）。
2. **SW 清单化**：预缓存从 6 个 URL 扩到 N+6；逐 URL 容错 install 逻辑已有，但「N 个文件的版本一致性」（缺一个文件 = 半个应用）是新事故面，`CRITICAL_PRECACHE` 判定要扩。
3. **CSP 是行为变更不是配置变更**：v3.7.56 记录过 CSP 放行的弯路教训（对照实验排负载混淆那次）；style-src 的 unsafe-inline 因内联样式大量存在仍要留，收紧只对 script-src 半效用。
4. **双轨分发 = 双轨验证**：e2e 今天全部走 file:// 单文件（104 例）；多文件形态只有起 http 服务才验得了，CI 要加 serve + 第二套入口，否则「双交付」里有一份长期低覆盖——违反本仓「判据以 CI 为准」（R9）。
5. **「真相源唯一」纪律回潮**：双态纪律（R8）+ 五源版本 + 单文件真相源是 v3.7.132 刚加固的；第二交付形态会制造新的「哪份为准」模糊——这是架构债，不是工程债。

## 四、备选：更低成本拿 CSP 收益？

- **hash 白名单**（`script-src 'self' 'sha256-…'`，构建期算 38 块哈希写进 CSP meta）：对内联 `<script>` 块有效，但 ① 每次构建 CSP meta 都要重算（自指问题可解：meta 不覆盖自身）；② **对内联事件属性（`onclick=` 等大量存在）完全无效**——那才是 unsafe-inline 的真实敞口，不清掉它，收紧只是心理安慰；③ style-src 同样无解。⇒ 要真收紧得先做「内联事件属性清除」，那是独立的 P0 级工程（约等于把全部 `on*=` 搬 addEventListener），与多文件交付无关。
- **结论**：CSP 收益不与多文件绑定；多文件不必然换来干净 CSP（事件属性不清，script-src 仍留 unsafe-inline）。这条「硬收益」实际不成立为多文件的理由。

## 五、结论

**暂缓（不做）。** ROI 表第 10 项 →「已评估 → 暂缓（本文件）」。理由一句话：三条收益里两条量级小、一条（CSP）拿不干净；成本五条全是实的，其中第 4/5 条直击本仓刚焊死的验证纪律与真相源纪律。

**重启评估的触发条件（任一命中即排期）**：

| # | 触发条件 | 观测方式 |
|---|---|---|
| ① | 交付态 > 6MB，或低端机首屏实测 > 2s | `check-source-state` 体积 + 低端机手测 |
| ② | SW 预缓存总大小逼近域名配额（5MB 量级） | PRECACHE_URLS 体积账 |
| ③ | 出现必须去掉 `script-src 'unsafe-inline'` 的合规/审计要求 | 外部要求 |
| ④ | 新增「外部静态托管按文件缓存」的部署形态（对象存储/CDN 直托） | 分发面变化 |

若触发：先做 §四 的「内联事件属性清除 + hash 白名单」预研（约 1 天）；仍不够再排多文件
（预估：构建分支 2–3 天 + SW 清单化 0.5 天 + CI serve/e2e 1–2 天 + 三视口回归 1 天）。
