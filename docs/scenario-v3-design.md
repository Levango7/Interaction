# 六大场景功能体系重构设计方案（v3.0 提案）

> 状态：**待审核**（未实施）
> 日期：2026-08-26
> 范围：场景标题栏 / 任务看板布局 / 六大场景功能体系 / 数据存储 / 检索展示调用 / 交互布局

---

## 一、现状分析

### 1.1 系统架构（已确认）

| 层 | 机制 | 说明 |
|---|---|---|
| 数据层 | `localStorage` + `PREFIX="wb_agent_"` | 任务 `tasks`、场景记录 `rec_{sc}`、配置 `cfg`、笔记 `notes`、习惯链 `links`、工具数据 `tool_{id}`、AI 会话 `ai_sessions`、记忆 `memory`、目标 `goals` |
| 渲染层 | `renderMainHTML()` 组装场景页 | 任务卡 + 资料库卡 + `renderSceneSections()`（场景扩展区）+ `renderExtra()`（专属卡，`CARD_REGISTRY` 查表） |
| 交互层 | `bind*()` 函数绑定事件 | 表单提交、按钮点击、看板拖拽 |
| 扩展机制 | `registerCard()` / `registerSceneSection()` / `TOOL_APPS` 注册表 | 新增卡片/区块/工具无需改主渲染函数 |
| AI 层 | `TOOLS` 数组（function-calling） | 已有 17 个工具：任务 CRUD、资料增查、搜索、记忆、目标编排、导出 |

### 1.2 现有能力盘点（19 个工具 + 6 场景专属卡）

| 簇 | 工具 |
|---|---|
| 文档 | Markdown、Word、表格、幻灯片、PDF、OCR |
| 设计 | CAD 画布、图片滤镜、AI 文生图、AI 视频生成（占位） |
| 学习 | 在线检索 |
| 编程 | 代码运行器、正则测试器、MD 转代码 |
| 生活 | 运动、缴费、采购、外卖、出行 |

### 1.3 已确认的问题

1. **场景标题栏只是标题栏**：`renderSceneHead()` 仅显示场景名 + 任务视图名 + 副标题，无功能入口。
2. **任务看板布局不合理**：
   - 表单 `align-items:flex-end` 导致「添加」按钮与输入框不等高；
   - `.fld` 有 `max-width` 限制（120~200px），表单未左右铺满卡片，显得局促。
3. **六大场景业务单薄**：多数场景只有「任务看板 + 资料库 + 一个专属卡」，数据/设计/生活专属卡无数据时不显示。
4. **编程与办公周报重复**（已在上轮修复为代码片段速览卡）。

## 二、场景标题栏与任务看板布局修复

### 2.1 场景标题栏 → 场景功能导航条

将 `renderSceneHead()` 升级为「标题 + 场景内功能 tab」：

```
┌─────────────────────────────────────────────────────┐
│ [场景图标] 办公 · 任务看板        [概览|任务|会议|项目|考勤|文档] │
│ 带截止日期的任务会汇总到下方「今天要处理」                    │
└─────────────────────────────────────────────────────┘
```

- 标题栏右侧新增场景内功能 tab（每个场景一组，见第三节）。
- 点击 tab 切换场景内视图（复用 `sceneViewMode` 的切换模式，新增 `sceneFeatureMode`）。
- 默认 tab =「概览」（现有任务看板 + 资料库 + 专属卡）。

### 2.2 任务看板布局修复

| 问题 | 修复 |
|---|---|
| 添加键与输入框不等高 | `.form-row` 的 `align-items:flex-end` → `align-items:stretch`，`.addbtn` 加 `min-height` 与输入框对齐 |
| 表单未铺满卡片 | 去掉 `.fld` 的 `max-width` 限制（或改 `flex:1 1 0` + `min-width`），让标题/标签字段铺满剩余宽度，按钮右对齐 |

## 四、视频生成 / 图片生成是否纳入

| 能力 | 现状 | 评估结论 |
|---|---|---|
| **图片生成（des-imggen）** | 已有真实实现：输入描述 → AI 返回 SVG 简笔示意并渲染（需配置 AI API Key） | ✅ **纳入**设计场景，作为 AI 创作能力（依赖 AI 配置，未配置时按钮禁用 + 提示） |
| **视频生成（des-vidgen）** | 当前是占位：点击提示「视频生成通道暂未开放」 | ⚠️ **暂不纳入主设计**。视频生成需专门视频模型/服务，当前接入的文本模型不支持；保留为预留能力（未来接视频模型后自动启用） |

**建议**：图片生成纳入设计场景「AI 创作」；视频生成保留入口但标记「即将上线」，不做主功能。

## 五、数据存储方案

### 5.1 总体原则

- 沿用现有 `localStorage` + `PREFIX="wb_agent_"` 体系，每功能一个存储键。
- 数据结构：数组（记录列表）+ 对象（配置），沿用 `load()/save()` 封装 + `scheduleAutoBackup()` 自动备份。
- 容量：localStorage 约 5MB 配额；现有 `AUTO_BACKUP_MAX_BYTES=1.5MB` 防写爆；大数据（图片/3D）建议存文件引用或压缩，不入 localStorage。

### 5.2 各功能数据结构

| 功能 | 存储键 | 数据结构 |
|---|---|---|
| 会议管理 | `meetings` | `[{id, title, date, who[], agenda[], followup, done}]` |
| 项目管理 | `projects` | `[{id, name, milestone, status, taskIds[], progress}]` |
| 考勤打卡 | `attendance` | `[{id, date, checkIn, checkOut, note}]` |
| 报销管理 | `expenses` | `[{id, title, amount, category, date, status, note}]` |
| 知识库 | `knowledge` | `[{id, title, category, tags[], content, createdAt}]` |
| 阅读笔记 | `reading` | `[{id, book, excerpt, note, progress}]` |
| 练习题库 | `exercises` | `[{id, subject, question, options[], answer, explain}]` |
| 模拟考试 | `exams` | `[{id, title, date, score, total, detail[]}]` |
| 数据分析报表 | `data_reports` | `[{id, title, dims, metrics, rows[], createdAt}]` |
| 数据可视化 | `data_charts` | `[{id, title, type, config, data[]}]` |
| UI 设计 | `design_ui` | `[{id, title, type, palette, components[]}]` |
| 3D 渲染 | `design_3d` | `[{id, title, format, dataUrl, note}]` |
| 前端页面设计 | `code_frontend` | `[{id, title, html, css, js, preview}]` |
| SQL 生成 | `code_sql` | `[{id, title, schema, sql, note}]` |
| 计划管理 | `life_plans` | `[{id, title, type, date, done}]` |

### 5.3 容量与清理

- 新增功能沿用「最近 N 条 + 手动删除」的轻量模型，避免膨胀。
- 图片/3D 等二进制内容：存 `dataUrl` 需控制体积（建议单条 <200KB），或提示用户用外部文件 + 引用路径。
- 全量数据仍由现有「导出/导入/清空」统一管理。

## 六、检索 / 展示 / 调用方案

### 6.1 检索

- **全文搜索**（顶栏 Ctrl+Shift+F）：把新增功能数据（会议/项目/知识库/题库/报表/UI/SQL/计划等）纳入搜索索引，关键词高亮。
- **主页全局搜索**：同上，跨场景检索。
- **场景内搜索**：各功能卡内提供过滤框（复用 `tool-filter-bar`）。

### 6.2 展示

- 每功能一个卡片，场景内 tab 切换（见第七节布局）。
- 功能详情/编辑：弹窗（`openModal` 模式）或抽屉（`openDrawer` 模式）。
- 列表用现有 `tool-table`，表单用 `tool-form-grid`，统计用 `tool-summary`。

### 6.3 调用

- **AI 工具注册**：在 `TOOLS` 数组为每个新功能注册 function-calling 工具，如：
  - `create_meeting` / `list_meetings`（会议）
  - `add_knowledge` / `search_knowledge`（知识库）
  - `generate_report` / `create_chart`（数据）
  - `run_sql` / `build_sql`（编程）
  - `add_plan` / `check_plan`（生活）
- 沿用现有工具执行器（`_aiChatText` + 工具分发），新增工具只需注册定义 + handler。
- 工具数据操作统一走 `_toolData/_toolSave` 或 `load/save` 封装。

## 七、交互与页面布局方案

### 7.1 场景页整体布局（改造后）

```
┌──────────────────────────────────────────────────────────┐
│ [场景图标] 办公 · 任务看板      [概览|会议|项目|考勤|文档]  │  ← 标题栏 = 功能导航条
├──────────────────────────────────────────────────────────┤
│ 功能 tab 内容区（默认「概览」= 现有任务卡+资料库+专属卡）     │
│ 其他 tab = 对应功能卡片（表单 + 列表 + 统计）              │
└──────────────────────────────────────────────────────────┘
```

### 7.2 交互流程

1. 点击标题栏功能 tab → 切换 `sceneFeatureMode` → 重渲染主区。
2. 功能卡内「添加」→ 展开表单 → 提交 → `save()` → 重渲染 + toast。
3. 列表项「编辑/删除/完成」→ 复用现有 `data-*` 属性 + 全局事件绑定模式。
4. AI 调用：聊天面板输入自然语言 → AI 调注册工具操作对应功能数据。

### 7.3 布局协调性

- 修复任务表单：`align-items:stretch` + 去掉 `max-width`，按钮与输入框等高、表单铺满。
- 各功能卡统一使用现有组件（`tool-form-grid`/`tool-table`/`tool-summary`），保证视觉一致。
- 响应式：沿用现有 4 断点；窄屏功能 tab 横向滚动。

## 十、求同存异设计原则（用户确认）

> **核心**：六大场景「同」的地方风格、布局一致，让用户一眼熟悉；「异」的地方对症下药，每种场景有其专属业务功能。

### 10.1 求同（统一骨架，六大场景一致）

| 维度 | 统一设计 |
|---|---|
| 场景标题栏 | 一律「场景图标 + 场景名 · 当前视图 + 功能 tab 导航条」，样式完全一致 |
| 基础模块 | 每场景必有「任务看板 + 场景资料库」两大基础卡（已存在） |
| 功能卡片 | 一律用 `tool-form-grid`（表单）+ `tool-table`（列表）+ `tool-summary`（统计）组件 |
| 卡片标题 | 一律「图标 + 标题」，图标独有且与标题语义对应 |
| 空状态 | 一律 `extra-empty` 引导「暂无记录 · 在上方资料库添加第一条」 |
| 交互 | 添加/编辑/删除/完成 走同一套 `data-*` 属性 + 全局事件绑定 |
| 配色 | 沿用各场景主题色（`--sc` 变量），卡片边框/悬停统一 |

### 10.2 存异（对症下药，各场景专属）

| 场景 | 专属业务（异） |
|---|---|
| 办公 | 会议 / 项目 / 考勤 / 报销（事务型：审批流、状态流转） |
| 学习 | 知识库 / 阅读 / 练习 / 考试（积累型：题库、评分、复习） |
| 数据 | 报表 / 可视化（分析型：维度汇总、图表生成） |
| 设计 | CAD / 图片 / UI / 3D（创作型：画布、原型、渲染） |
| 编程 | 运行器 / 正则 / 前端 / SQL（工程型：执行、测试、生成） |
| 生活 | 计划 / 健康 / 缴费 / 采购（日常型：打卡、提醒、清单） |

> 每个场景的功能 tab、字段、统计维度、操作按钮均因场景业务而异，但外层骨架统一。

## 十一、创意补充（AI 设计）

在用户指定功能之外，补充以下轻量创意（均为纯前端离线、可独立开关）：

1. **办公·会议纪要一键生成**：会议管理卡内「生成纪要」按钮，把议程+结论自动排版为可复制的纪要文本（复用周报生成器思路）。
