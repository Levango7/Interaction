# 桌面萌宠系统（Pet System）

> 适用版本：v3.6+ ｜ 唯一真相源：`agent-workbench.html`
> 相关代码：搜 `_petArtMarkup` / `_petSvgFor` / `mountPet` / `placeFace` / `PET_ORDER`

右下角常驻一只会动、会眨眼、会说话的角色。本文档说明**数据结构、素材管线、五官标定、风格渲染**，以及**如何新增一只角色**。

## 二、数据结构（7 张表，全在单一 HTML 内）

| 名称 | 作用 | 备注 |
|---|---|---|
| `_PETS` | 老注册表：`name` / `desc` / `bubbles`（点击说话的文案，每只 5 条）/ `svg`（手绘兜底） | 只有 AI 立绘的角色可不带 `svg` |
| `_PETS_V2` | 风格化绘制注册表：`name` / `desc` / `draw[styleId]()` | 弹窗卡片顺序**不**看它的键顺序，看 `PET_ORDER` |
| `_PET_ART` | AI 立绘（透明底 PNG，base64 data URI） | 9 只，长边统一 320 |
| `_PET_FACE` | 五官标定（归一化坐标） | 见第四节 |
| `_PET_ART_SCALE` | 按角色的整体缩放 | 目前只有全身人物 `lady` / `boy` = 1.5 |
| `PET_SIZES` | 尺寸三档：`s`=72 / `m`=96（默认）/ `l`=128 | 偏好键 `petSize` |
| `PET_ORDER` | 弹窗展示顺序 | 未登记的角色自动排到末尾 |

偏好键（localStorage，前缀 `wb_agent_`）：`pet`（当前角色）、`petSize`（尺寸）、`petStyle`（风格）。

## 三、立绘素材管线（构建期，纯 Node，零 GPU）

**立绘数据已外置（v3.7.5 起）**：9 张 PNG 放在 `assets/pet/`，源码态 `agent-workbench.html`
**不含 base64**（占位为 `const _PET_ART = { /*PET_ART:BEGIN*/ /*PET_ART:END*/ };`），
由 `scripts/pet-art.mjs` 在构建/测试前回注。**代码**仍以 HTML 为唯一真相源（与 build.mjs 的
「不做 src→HTML 字节拼接」定稿不冲突：外置的只是**素材数据**，不是代码）。

```
AI 生成 1024²（要求：中调纯色背景 #8FA3B8、无水印、全身）
   ↓  pet-lib.js cutout()          洪水填充抠底（自适应容差）+ 内容包围盒
   ↓  areaResize()                 面积平均降采样（预乘 alpha，防白边）
   ↓  encodePNG()                  逐行自适应 PNG 滤波（5 种挑绝对值和最小，无损省 25~40%）
   ↓  assets/pet/<kind>.png        ← 仓库里的素材真相源（9 张合计 637KB）
   ↓  scripts/pet-art.mjs         回注：base64 塞回 _PET_ART（顺序由 order.json 保持）
   ↓  单文件交付 agent-workbench.html
```

| 命令 | 作用 |
|---|---|
| `npm run pet:inject` | assets → HTML（幂等；默认行为） |
| `npm run pet:extract` | HTML → assets（同时把 HTML 置回源码态） |
| `npm run pet:check` | 校验两侧一致 |

`npm test` / `npm run build:check` / `npm run build:prod` 均挂了 `pre` 钩子自动回注，
CI 与发版不需要额外步骤；**只有本地直接双击打开源码 HTML 时才需要手工 `pet:inject`**
（否则立绘为空：控制台有告警、5 个原始角色退化为 SVG 兜底，属预期行为）。

### 显示尺寸与素材分辨率的关系（降采样依据）

档位 `s/m/l` = 72/96/128 px；`lady` / `boy` 另有 `_PET_ART_SCALE = 1.5`（全身立绘横向太窄，需放大）。
按 DPR=2 推算最大设备像素需求 = 128×2 = **256**（有 1.5× 缩放的两个角色 = 384）：

| 角色 | 素材长边 | 依据 |
|---|---|---|
| 其余 7 只 | **256** | 恰好覆盖 128px 档 @DPR2，再大是浪费（1180KB → 637KB） |
| `lady` / `boy` | **320** | 有 1.5× 缩放，需要更多像素 |

**要点：降采样必须用面积平均**（双线性只取 2×2 邻域，缩小 ≥3× 会严重混叠、边缘发糊）。

## 四、五官标定（`_PET_FACE`）

单张立绘没有部件，眨眼 / 张嘴靠**贴一层浮层**实现。字段：

```js
lady: { l:[0.400,0.163], r:[0.550,0.163], ew:0.085, eh:0.022, m:[0.478,0.205],
        skin:"#f7e8de", lash:"#3a2c2e" }
```

| 字段 | 含义 |
|---|---|
| `l` / `r` | 左 / 右眼中心（归一化，原点 = 图片显示矩形左上角） |
| `ew` / `eh` | 单眼宽 / 高占比 |
| `m` | 嘴中心 |
| `skin` / `lash` | 闭眼遮罩色 / 睫毛线色（构建期从原图 3×3 邻域采样后写死，运行时零 canvas） |

**标定方法（重要）**：不要靠放大截图肉眼估读 —— 截图会被缩放，按屏显像素读误差可达 ±2%（在 320px 素材上就是 ±6px，而眼睑只有 6px 宽，必然错位）。

正确做法用标定页（`_diag/gen-calib.js` + `shot-calib2.js`）：
每格 = 立绘 + **归一化网格（2% 细线 / 10% 粗线）** + **当前参数下的浮层叠加** + 角色名 → 一屏看全、对齐检查与坐标读数在同一张图完成；网格是百分比，与屏显缩放无关。坐标写在 `face-guess.json` 里迭代，改 JSON 不改代码，通常 2 轮收敛。

浮层落位在运行时计算（`placeFace()`）：按 `object-fit: contain` 的实际显示矩形换算成 px；**依赖布局尺寸，必须等 `appendChild` 之后**，且不能只靠 `load` 事件（data URI 可能早已触发）——用 rAF 重试到成功。

## 五、风格系统（两档）

| 风格 | `petStyle` | 实现 |
|---|---|---|
| 精致二次元 | `anime` | 直接用 `_PET_ART` 平涂稿 |
| 3D 立体渲染 | `toon3d` | **同一张清晰立绘 + 2.5D 渲染**（不换素材） |

### 为什么 3D 档不用"另生成一套 3D 稿"

试过用 img2img 重渲染一版 3D 稿 —— **细节必然糊**（橘猫糊成深褐杂色、萨摩耶长出黑斑）。在 64~128px 的桌面宠物上尤其明显。
也试过让模型"少画点阴影"重出图 —— **更糟**，模型把指令理解成加黑描边 + 黑斑。

最终方案：**同一张清晰立绘 + CSS 2.5D**，细节零损失、文件还更小（删掉整套 3D 稿省了约 0.5MB）。

### 2.5D 渲染的组成

| 手段 | 实现 |
|---|---|
| 厚度挤出 | 2 层很薄的同向 `drop-shadow` + 一层淡软投影（早期用 3 层不透明深色，在浅色毛上会压出黑斑） |
| 方向光 | **把同一张立绘再叠一层当遮罩**：`mask-image` 用「左上亮 → 右下暗」斜向渐变 + `mix-blend-mode: soft-light`。**不新增素材、不改一个像素就能重新打光**；暗部从 34% 起就开始缓慢过渡（早期 50% 起陡降、末端 0.78，会糊出假阴影） |
| 镜面扫光 | 同一技巧：白色高光带 + `mask-position` 动画横扫（`pet3dSheen`），像手办表面反光 |
| 接地影 | 脚下椭圆软影 |
| 转台摇摆 | 绕 Y 轴 ±9° 缓慢来回。**要点**：角度自定义属性必须用 `@property --ptsy { syntax:'<angle>' }` 注册，否则 keyframes 无法插值；不支持的浏览器自动降级为静止 |
| 指针倾斜 | 鼠标在萌宠上移动 → `--ptx/--pty`（±16°/±12°），离开回正；与摇摆共用同一 transform 相加，互不打架 |
| 星光特效 | 立体档额外撒 ✦（十字光晕、随机方向飞散） |

> 因为两档底图相同，**眨眼 / 张嘴浮层两档通用**（同一套 `_PET_FACE` 坐标）。

## 六、尺寸与定位

- 显示尺寸由 CSS 变量 `--pet-size` 控制，默认 96px（原为 64）。
- 默认落位按实际尺寸留边（`window.innerWidth - size - 42`），不再写死偏移量。
- 全身立绘横向窄、头身比小，同样盒子里视觉体量偏小 → 用 `_PET_ART_SCALE` 整体放大（缩放挂在 `.pet-art` 外层，眨眼浮层随之等比缩放，不会错位）。
- **点击处理中重建 DOM 的坑**：点尺寸 / 风格标签时若同步重建整个弹窗 DOM，松手时命中的已是新节点，会连带触发某张卡片的 `onclick`（实测：点「中」，角色被换成另一只）。对策：`preventDefault + stopPropagation` + 把重渲染 `setTimeout(...,0)` 推迟到下一拍。

## 七、动作 / 眨眼 / 说话 / 特效

- **动作**（`playAct`）：摇头 / 点头 / 跳舞 / 倾斜 / 转圈，作用在 `.pet-art-img`；与父层 `.pet-art` 的摇摆 / 倾斜叠加。
- **眨眼 / 张嘴**（`blinkArt` / `talkArt`）：靠 `_PET_FACE` 的浮层。
- **心跳**：定时随机触发；立体档额外撒星光；长时间无操作出 `z Z`（睡觉）。
- 点击萌宠 → 随机说一句 `bubbles` 里的台词。

## 八、新增一只角色（标准流程）

1. **出图**（ImageGen，图生图保持风格一致）：
   - 提示词点名**具体日常单品** + 成组否定（`no fantasy costume / no armor / no gold trim / no braid / no weapons`，换物种加 `not a Shiba, not a Japanese breed`）。
   - 明确要求**中调纯色背景 `#8FA3B8`、无水印、全身**。
   - 涉及"稍微性感"的分寸：只对成人角色用，并显式写 `no lingerie / no swimwear / nothing vulgar / no exaggerated body emphasis`；**幼年角色一律纯日常**。
   - 要"某明星那种感觉" → **只提取风格方向**，不描述 / 复制具体真人面部。
2. **处理**：`node _diag/pet-add.js`（或对应脚本）→ 得到 `petgen2/art3/<kind>.png` + base64 JSON。
3. **注入**：把 base64 并入 `_PET_ART`；在 `_PETS` 加 `name/desc/bubbles`，在 `_PETS_V2` 加 `name/desc`；需要时在 `_PET_ART_SCALE` 加缩放；把 kind 写进 `PET_ORDER`。
   > 注入一律用**精确锚点替换**，改完必须逐块 `node --check`（`_diag/chk-all.js`）。历史上曾因"用 `indexOf('};')` 定位对象收尾"把条目插进错误的表里，也因"新条目缺尾逗号"整页白屏。
4. **标定五官**：`_diag/gen-calib.js <kind>` → 截图 → 读网格 → 写 `face-guess.json` → 迭代到对齐（通常 2 轮）。
5. **验证**：`_diag/verify-*-cdp.js`（Edge headless，走 CDP）：卡片数 / 立绘加载 / 两档风格 / 浮层落位 / 横向溢出 / 控制台错误。
6. **发版**：`npm run build:check` → 提交 → push（CI 自动部署 gh-pages）。

## 九、踩坑清单（按代价排序）

1. **抠图吃掉主体**：浅色主体 + 浅灰渐变背景 → 自适应容差 + 中调纯色背景。
2. **img2img 重渲染糊细节**：追求"立体"改用同图 2.5D。
3. **放大截图读坐标误差 ±2%**：用归一化网格标定页。
4. **`@property` 未注册 → 角度无法插值**：转台摇摆失效（静默降级）。
5. **点击中重建 DOM → 误触新节点**：阻断冒泡 + 延后重渲染。
6. **用正则改 JSON**：曾把 `"screenshots":` 键吃掉导致 JSON 非法。**改 JSON 一律解析再序列化**。
7. **版本号四处漂移**：`build:check` 会拦，发版用 `npm run release`。
8. **`git add -A`** 会把 `.playwright-mcp/` 等会话产物带进提交 → 用精确 `git add <文件>`。
