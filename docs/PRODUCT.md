# PRODUCT.md · 产品定位与取舍（活文档）

> 状态：**活文档（2026-10-20 起）**。本文件是"要不要做某个功能"的唯一裁决依据；
> 与 `docs/product-scope.md`（能力清单）、`docs/roadmap-2026Q4.md`（排期）分工如下：
> 本文件回答**为什么做、给谁做、不做什么**，那两份回答**有什么、什么时候做**。
> 冲突时以本文件为准，并回来改那两份。

## 1. 一句话定位

> **一个 AI 能真正动手的单文件个人工作台**：任务、资料、计划都在一个 HTML 里；数据默认只在自己手里；
> AI 不是聊天框，是能改数据、建任务、跑流程的执行者。

三个卖点必须同时成立，缺一个就不是这个产品：
1. **单文件交付**（可离线、可拷走、可归档，无安装、无账号）。
2. **本地优先**（默认不联网；联网是一次显式选择，不是前提）。
3. **AI 落手**（能读你的数据、改你的数据、替你推进任务，而不是只回话）。

## 2. 用户

**主用户**：重视数据主权的独立开发者 / 研究者 / 知识工作者。
特征：愿意为"数据在谁手里"付出配置成本（自带模型 Key、必要时自建同步服务）；任务多、资料散、
已经在用 markdown / 笔记 / 待办工具但都不满意；能接受"配置 10 分钟，用一年"。

**明确不是我们的用户**：团队/企业采购、需要审批流与多人协作的组织、纯手机轻用户、
不愿配置任何 Key 的大众消费者。

## 3. 反目标（写下来是为了砍需求）

- 不做团队协作、共享空间、多人权限。
- 不做企业多租户、SSO、审计合规套件。
- 不做多文件工程（单文件是产品，不是技术债）。
- 不做社交、社区、模板市场分成。
- 不做通用低代码 / 流程编排平台。
- 不做"什么都能集成"的集成中心；只做**能把任务送出去/收回来**的少数几条链路。

任何新需求，先问：它服务第 1 节那三个卖点中的哪一个？答不出就进 Labs 或不做。

## 4. 核心闭环（所有页面必须服务它）

**捕获 → AI 落手 → 复核 → 沉淀/带走**

| 环节 | 用户动作 | 产品必须提供的 | 当前状态 |
|---|---|---|---|
| 捕获 | 记下一件事 / 导入一份资料 / 接到一条消息 | 3 秒内能记下：首屏主 CTA、全局快捷键、命令面板 | 首屏 CTA 2026-10-20 补上；`>`/Ctrl+K 已有 |
| AI 落手 | 让 AI 拆解、改期、归类、起草、跑工具 | 可见地读数据、改动可撤销、失败可解释 | 26 tools 已接线；**单步通用撤销**覆盖任务/资料库记录/笔记/知识库文件（含手工改动，2026-10-23；联动新任务不连带）；可解释仍缺 |
| 复核 | 看 AI 改了什么、确认或回滚 | 变更清单 + 一键撤销 + 动作留痕 | 部分：AI 回执条可撤销；完整动作日志仍缺 |
| 沉淀/带走 | 导出/备份/同步/离线继续 | 一份可信的备份 + 明确的同步状态 | 备份/导出完整；同步需自建服务 |

判定：**不属于这四步的功能，一律进 Labs（见 §6），不进主界面。**

## 5. 信息架构（三区）

- **Today（今日）**：待办 + 继续上次 + 一键新建 + 今日 AI 动作。
- **Work（工作台）**：任务 / 看板 / 日历 / 资料库 / 笔记；场景是**视图模板**，不是功能目录。
- **Assistant（助手）**：对话 + 工具调用 + 技能 + 记忆；`>` 命令面板是键盘入口。
  2026-10-21 布局 v2 起：**助手面板就是主列底部的对话坞**（不再占右侧栏），历史可收起、输入行常驻；
  右栏改为**今日任务轨**——只做"看和勾"，任务的唯一 CRUD 入口仍是任务页。
  2026-10-23 起再加三件事：① 对话坞上方的**真实运行进度**（流式字数 / 工具批次 N÷总数 / 计划步数，
  总数未知走不确定态，绝不做假百分比）；② 悬停 AI 回复可见**触发它的那句原话**；
  ③ 右栏分三页（今日 / Agent / 文件），**只列真能力**——技能来自真注入的 `listEnabledSkills`、
  文件来自 `getRagFiles`，而 MCP 仍是配置壳（按 §6 诚实条款不给它主界面入口）。
  AI 输出的可读性也归这里：Markdown 渲染覆盖表格与引用块，mermaid 代码块用随包的本地产物画成图
  （严格安全模式 + 产物二次消毒），画不出来时保留源码并写明原因，不留空白。

导航硬约束：**主路径层级 ≤3**；同一能力**只保留一个主入口**（其余入口只能作为上下文快捷方式）；
AI 入口收敛到 2 处（助手面板 + 命令面板）。

## 6. 功能分层

| 层 | 含义 | 例子 |
|---|---|---|
| **核心** | 服务闭环，必须有、必须好用 | 任务 CRUD/看板/日历、资料库、AI 工具调用、备份导出、离线 |
| **增强** | 核心的延伸，默认开启但不占主路径 | RAG/笔记、统计报表、ICS/WebDAV、通知 |
| **Labs** | 有价值但不在闭环上，默认收起、明确标注实验性 | 工具箱的非高频卡片、甘特/思维导图/仪表盘、萌宠、番茄钟 |
| **不做** | 见 §3 | 协作、企业、多文件、社交 |

**诚实条款**：任何未完成或演示性质的能力，必须在 UI 上标注（示例数据 / 需自建服务 / 未接入），
不得用"预告""即将上线"长期占位；`mock` 数据不得以产品能力的口吻呈现。

## 7. 设计原则（UI 与交互裁决用）

1. **行动优先于报表**：首屏第一眼是"能做什么"，不是"已经怎样"。
2. **默认本地、联网显式**：任何出网动作要么由用户点击触发，要么在设置里明确开关。
3. **AI 的改动可见、可撤销、可解释**：没有 undo 的写操作不允许上线。
   现状（2026-10-23）：**单步通用撤销**已覆盖任务（创建/更新/完成/删除）、资料库记录、笔记、
   知识库文件（导入/同名替换/删除，含手工改动），50 步历史 + 10 秒可见入口；不做无限栈/跨设备撤销，
   联动新任务不连带；长期记忆仍在账外。
4. **演示级能力不进主界面**：假数据、假连接、假集成只允许出现在 Labs 且带标记。

## 8. 指标（北极星 + 护栏）

- **北极星**：每周"完成闭环"的用户数——同一周内至少一次 捕获→AI 落手→复核 的完整动作。
- 过程：首次成功任务时间（新用户）、AI 动作成功率、撤销率、7 日回访率。
- 护栏：静默失败率（无提示的 catch / 总数）、死入口数（可见但无响应）、包体与首屏时间、
  数据丢失事件数（必须为 0）。
