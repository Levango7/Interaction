**为什么会看错**：`.catch` 与 `catch(e)` 在同一片代码里挨着，凭印象归类而不是逐条读源码 ——

### 2.2 真正的根因（已用脚本实证）

`scripts/lib/empty-catch.mjs` 的 `findEmptyRejectionHandlers()` 用**整形状正则**判空：

```js
/\.(?:catch|then)\s*\(\s*(?:[A-Za-z_$][\w$]*\s*,\s*)*(?:function\s*\([^)]*\)|(?:\([^)]*\)|[A-Za-z_$][\w$]*)\s*=>)\s*
  \{\s*(?:\/\*[\s\S]*?\*\/|\/\/[^\n]*)*\s*\}/g
```

两个独立的缺陷：

1. **惰性跨段匹配（主因）**：`\{\s*(?:\/\*[\s\S]*?\*\/)*\s*\}` 里的 `[\s\S]*?` 会**一直往文件后面扩张**，
   直到找到某处 `*/`，且该 `*/` 之后只隔空白就紧跟 `}` —— 于是整体匹配成功。
   ⇒ **处理器体里首句是注释、后面跟着真实语句**时，会被判成「空」。
   实证：`ui-backup-stats.js:401` 匹配到的原文是
   `.catch(function(e){\n /* R-2… */ \n try{ if(typeof pushDiag…`（**体里有 pushDiag**）。
2. **不判注释/字符串（次因）**：该函数在 **raw 原文**上跑，从不剥注释 ⇒
   注释里**引用的旧代码**也会被当真代码计数。实证：`ui-backup-stats.js:878`
   （落在描述 R-34 假回执的块注释里，引的是修掉之前的旧写法）。
