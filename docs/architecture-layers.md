## 〇、Core Layer（核心层·v3.7.9 新增）

**位置**：`src/core.js`，在层序最前（脚本内最先求值）。

**放什么**：被绝大多数块共用的「全局助手」与基础数据 —— 目前是 `UI_ICONS`（52 个内联图标）、
`t`（i18n）、`toast`（通知）、`SCENARIOS`（8 个场景定义）、`ORDER`（内置场景顺序）。

**为什么**：`docs/module-graph.md` 的符号级实测显示，这些符号的扇出极高（v3.7.63 拆分后、35 块口径：
`t` 被 30 个块使用、`toast` 26 个、`SCENARIOS` 21 个、`ORDER` 17 个；块数越多扇出口径越大），
但它们原先散落在 UI 层的叶块里（如 `t` 在 `ui-global-events`、`toast`/`SCENARIOS` 在 `ui-theme`），
造成大量「低层块引用高层块符号」的逆层边。收敛到核心层后，依赖方向回归「下层被上层依赖」。

**硬约束**：核心层**必须零外部依赖**（不得引用任何其它块的符号）。
例如 `active` 虽然也是全局状态，但它的初始化调用 `load()`（定义在更靠后的 `data-rw`），
放进核心层会在加载时触发 TDZ 报错 —— 因此**不能**放进来。这条约束已由
`npm run check:modules`（依赖图校验：新增环/逆层/重复定义即失败）间接守护。

**层契约**：`scripts/lint-layers.mjs` 的 REQUIRED 已加入 `Core Layer`，缺失即 CI 失败。

## 三、依赖方向（拆分顺序的依据）

```
Bootstrap (常量/工具)
  └→ Data Layer ──→ Crypto Layer
         └──→ Chain Layer ──→ AI Layer ──→ Render Layer
                    └──────────→ UI Layer
```

- **Bootstrap / Data / Crypto / Util**：无 DOM 强依赖（或仅 localStorage），是**最安全先拆**的候选
- **Chain / AI**：依赖 Data + 部分 UI（toast），中等
- **Render / UI**：强 DOM 耦合，最后拆

## 三·补、模块依赖图：已知例外与门禁能力边界（2026-09-27 审计补充）

上面第三节画的是**目标方向**。实际依赖图与它并不一致 —— 本节的数字是实测，引用时以命令输出为准。

**现状（`npm run check:modules` 实测输出）**：

```
[module-graph] 块 35 · 重复定义 0 · 循环 50 · 逆层 53
[module-graph] check ✓ 无新增问题
```

即：**基线内固化着 50 条循环依赖与 53 条逆层依赖**，门禁仍然判「通过」（44→50、35→53 的上升是
v3.7.63 拆块的粒度效应，见本节末补充，不是新增耦合）。这不是 bug，是
`scripts/module-graph.mjs` 明确采用的**基线棘轮（ratchet）**策略：

> 基线内的既有项只报告、不失败；**新增**的逆层依赖/循环/重复定义才让 CI 失败。
> （`scripts/module-graph.mjs` 文件头自述；基线数据在 `scripts/module-graph.baseline.json`）

选这个策略的理由成立：还清 50 条环需要大规模重构，逼一次还清会让门禁长期为红而失去意义。
但由此产生三个**必须知道的能力边界**，否则会误以为「check ✓ = 分层契约成立」：

1. **「check ✓」的含义是「没有新增问题」，不是「没有逆层依赖」。** 现状有 53 条逆层边。
2. **经共享符号新增的逆层依赖不会被拦下。** 脚本自述：扇出 ≥ 8 的共享符号（`t` / `save` /
   `PREFIX` 等）不计依赖边 —— 于是「A 层调用 B 层的 `save()`」这类新增逆层是隐形的。
   想看全量边用 `--fanout=1`。
3. **新增一个窄符号（扇出 < 阈值）可能闭合出新的环**，脚本注释承认这属真实结构变化而非误报 ——
   也正因如此，环/逆层的数量会随普通功能开发缓慢上升，只要不超过基线就一路绿灯。

**要做的事**：
- 引述本文件第三节时，**必须同时说明「存在 53 条已知逆层例外」**，否则读者会以为契约已成立。
- 若某次改动让 `check:modules` 报「新增 N 项」，那是真实的结构变化：要么修，要么跑
  `npm run module:freeze` 更新基线（后者等于接受该例外，应同时在上表登记原因）。
- 想了解当前全貌：`npm run module:graph`（写 `docs/module-graph.md`）。

> 补充（v3.7.63 拆分记录）：`src/ui-global-events.js` 曾是全仓最大的块（8,566 行 / 376KB）。
> 它的层注释写的是「交互层·全局事件绑定」，但实际承载了集成/OAuth2 残留/各类列表渲染等
> 本应属于其它层的内容 —— 是逆层边的主要成因，也是后续拆分收益最高的一块。
> 现已按 section 拆成 8 块：`ui-global-events`（2,238 行）+ `ui-ge-api` / `ui-ge-plugins` /
> `ui-ge-theme` / `ui-ge-pomodoro` / `ui-ge-calendar` / `ui-ge-notes` / `ui-ge-integrations`
> （后 7 块合计 6,333 行）。拆分为**纯位移**：拼回产物与拆前逐字节等值（src-split 往返校验）。
> 循环 44→50、逆层 35→53 是**粒度展开的计数变化，不是新增耦合** —— 把 8 块合并回单块、
> 用同一分析逻辑重跑，结果与旧基线逐项完全一致（0 差异）。

## 四、渐进拆分路线图（每步可独立交付）

| 步骤 | 目标 | 收益 | 风险 |
|---|---|---|---|
| ① 分层契约（本轮） | `lint-layers.mjs` 校验边界 | 防漂移基线 | 低（只读脚本） |
| ② 抽取 Util Layer | mdToHtml / 性能工具 → 独立文件，构建时拼接回 | 首个"真模块" | 中（需构建拼接） |
| ③ 抽取 Crypto/Data | 加密 + 存储层独立 | 数据层可单测 | 中 |
| ④ 抽取 Chain/AI | 习惯链 + AI 引擎独立 | 逻辑层解耦 | 中高 |
| ⑤ Render/UI 渐进 | 最后拆分（DOM 耦合最强） | 完全模块化 | 高 |

> ⚠️ 关键约束：交付物始终是单文件（file:// 直开 + 三种运行形态共用），
> 拆分必须通过"构建时拼接回单文件"实现，不能改为运行时多 `<script src>`（file:// 下会失败）。

---

## 五、新增分层规范

- 新增 JS 功能块时，用 `// ===== <Name> Layer (<说明>)` 注释开头（与现有格式一致），`lint-layers.mjs` 自动纳入校验。
- 删除模块时，同步删除注释标记；`lint-layers` 的"连续层间必须有内容"规则会兜住"删空"。
- 关键层（Bootstrap/Data/AI/Render/UI/Util/Crypto/Chain）缺失时校验 fail。
