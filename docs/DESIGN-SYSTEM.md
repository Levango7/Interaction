# DESIGN-SYSTEM.md · 视觉与交互契约（活文档）

> 状态：**活文档（2026-10-20 起）**。本文件规定**必须遵守的设计契约**；
> `docs/ui-standards.md` 保留为实现细节与历史说明。冲突时以本文件为准。
> 已有门禁：`lint-tokens` / `lint-css-structure` / `lint-breakpoints` / 三态渲染测试 / 元素级溢出 e2e。

## 1. 令牌（tokens）

- 所有颜色、间距、圆角、阴影、层级**只能**来自 CSS 变量；`src/*.js` 里禁止新增硬编码色值
  （现存 332 处是债务，按"改到哪清到哪"处理，优先 `render-widgets.js` 的侧栏 6 色）。
- 间距阶：4px 基线（4/8/12/16/20/24/32/40/48/64），不得出现 5/7/9/13 这类奇数裸值。
- 圆角：6 档（2/4/6/8/12/16）；控件与卡片不得自造新圆角。
- 字号阶：12/13/14/16/18/20/24/28/32；**正文最小 12px**，9–11px 只允许出现在纯装饰徽标上且必须可读（对比度 ≥4.5:1）。
- 层级：`--z-*` 六档（base/raised/sticky/overlay/modal/toast），新浮层必须选一档，不得写裸 z-index。

## 2. 断点

以 `scripts/lint-breakpoints.mjs` 的允许集为准（当前：主档 `1440/1439`、`1024/1023`、`768/767`；
细分档 `600/520/479/359`）。**不得新增断点值**；长期目标是收敛，但收敛必须同时改守卫与债务清单，
不允许"先写一个新值再说过渡"。

- 桌面 ≥1024、平板 768–1023、手机 ≤767 三档行为必须各自定义完整。
- 断点只用于**布局变化**，不用于隐藏功能差异（功能差异用能力检测）。

## 2.1 布局（v2，2026-10-21）

**定位依据**：`PRODUCT.md`——用户是桌面为主的知识工作者（数据主权、任务多、资料散），闭环是
「捕获 → AI 落手 → 复核」。所以：**对话要随手可用（底部坞），任务要始终可见（右栏轨）**，
而不是把 AI 关进第三栏、把任务藏进页面。

| 宽度 | 结构 | 聊天 | 任务轨 |
|---|---|---|---|
| ≥1024 | 左导航（可折） / 主列 / **今日任务轨 280px** | 主列**底部对话坞**（`sticky`） | 常驻，可折（折叠后顶栏出现「今日」按钮） |
| 768–1023 | 左导航 / 主列 | 同上（底部坞） | 默认移出视口，顶栏「今日」滑出；Esc / 点遮罩关 |
| ≤767 | 底栏 4 组 + 侧栏抽屉 | 保持右抽屉（核心用户不是纯手机用户，不动） | 顶栏「今日」滑出 |

- **对话坞**：默认**收起**（只留标题栏 + 输入行）；有显式偏好才恢复用户选择。展开时 `max-height:46vh`，历史区最高 `30vh` 自身滚动；
  **折叠 = 只收起历史与工具条，输入行与标题栏必须保留**
  （否则唯一的展开按钮会被藏掉——实测踩过）。展开/折叠持久化到 `wb_agent_chat_panel_collapsed`。
  沉浸页（`#drawer.drawer-page`、`.main.page-recycle`）**隐藏对话坞**：这些页面要全高，
  AI 仍可从命令面板进入（2026-10-21 实测：常驻坞把集成面板的 Linear 按钮挤出视口、让场景表单下拉被裁切）。
- **任务轨**：只做"看和勾"。排序 逾期 → 今天 → 有日期 → 无日期，最多 8 条；勾选走 `completeTask`
  （含联动规则），点标题走 `openTaskEdit`，`+` 走**首屏同一个新建入口**（切 office + 聚焦标题）。
  **禁止**在任务轨里长成第二套 CRUD——任务页仍是唯一主入口。
- **窄屏顶栏**：≤479 收起两个低频按钮（指南→侧栏底部 `#sideBtnHelp`；导出→设置·数据管理），
  为「今日」入口腾位置；这也是 2026-10-20 记的"低频按钮收口"设计项的第一刀。
- **守护**：`tests/task-rail.test.js`（排序/计数/完成/空态/折叠持久化/滑出）+
  `tests/e2e/layout-v2.spec.js`（几何：坞与主列同宽、轨在主列右、无横向溢出、折叠后主列变宽；
  含**反向对照**：偏移 40px 的盒子必须被同一判据判红）。
- **禁止**：在主列再叠第二条常驻浮层；用 `position:fixed` 假贴底（必须 `sticky` 留在文档流，
  以保证抽屉页/回收站的滚动语义不变）。

## 3. 控件尺寸与触控

- 三档高度：**28（sm）/ 36（默认）/ 44（触控/主操作）**；不得出现 26/30/48 等新值。
- 粗指针（触屏）下可点区域**高度** ≥44；宽度按所在容器而定 —— 顶栏图标按钮在 ≤479 目前是 **26px 宽**：
  实测把宽度抬到 40 会让 375px 视口出现 103px 横向溢出（顶栏按钮数量多），所以宽度下限必须等
  「窄屏顶栏低频按钮收进溢出菜单」这个设计项落地后再一起抬到 ≥40。**在此之前不许用压布局的办法凑 44×44 指标。**
  ⚑ 守护：`tests/ui-scale-floor.test.js` 钉住"窄屏高度 ≥40 / 粗指针 ≥44 / 宽度仍 26"这组**与实测一致**的契约。
- 主操作按钮在同一视图内**只允许一个**（视觉主色），其余用次色。

## 4. 浮层（Modal / Drawer / Sheet）

- 只允许三类：`Modal`（居中、阻断）、`Drawer`（侧边、设置/详情）、`Sheet`（底部、移动端选择）。
  不再新增第四种形态；现有 7 种逐步归并。
- 每个浮层必须：`role="dialog"` + `aria-modal="true"` + 标题关联；**Esc 关闭**；
  **焦点陷阱**（打开时聚焦首个可操作元素，关闭时焦点归还触发元素）；点遮罩关闭（确认类除外）。
- 同一时刻最多一层浮层（Sheet 覆盖在 Modal 上必须显式允许）。
- **浮层骨架只认这几个类名**：`.viz-modal` / `.report-modal` / `.overlay`（都是 `position:fixed` +
  `z-index:var(--z-modal)`）。⚠️ `.recycle-modal` **不是浮层** —— 它是页面内卡片（`position:static`），
  2026-10-21 实测它曾被当"危险操作确认"的外壳用：插到 body 末端时整块在视口外，窄屏下「确认执行」按钮
  被固定底部导航（`--z-sidebar:40`）压住，`elementFromPoint` 命中的是 `mob-bar-btn`。
  详见 `docs/audit-2026-10-06.md` R-29。
- **危险操作确认一律走** `dangerConfirm({title,message,detail,confirmText}) → Promise<boolean>`
  （核心层，`.viz-modal` 真浮层 + Esc 取消 + 焦点陷阱 + **不吃遮罩点击** + 全量转义）。
  原生 `confirm()` 由债务棘轮钉住只准减少（`tests/danger-confirm.test.js`，当前 39 处）。
- **"看得见、点得到"不许用 jsdom 证明** —— 它没有排版引擎，`getElementById` 恒真。浮层的可见性判据
  必须落 Playwright：盒子在视口内 + `elementFromPoint(中心)` 命中的就是自己，并配**反向对照**
  （拿旧骨架跑同一条判据必须判红），见 `tests/e2e/danger-confirm.spec.js`。

## 5. 状态

| 状态 | 规范 | 入口 |
|---|---|---|
| 空 | 必须给"下一步动作"，不能只写"暂无数据" | `renderEmpty(scene)`（已登记 key 才能渲染） |
| 加载 | 所有 >200ms 的异步按钮必须进入 busy/禁用态 | `withLoading(btn, promise)` |
| 错误 | 必须说明**发生了什么 + 下一步**，不得静默 | `renderErrorState` / `toast(..., "error")` |
| 成功 | 轻量 toast，不阻断 | `toast(..., "ok")` |

- toast 四类（ok/warn/error/info）必须有独立视觉（当前 error/info 无样式，属缺陷）。
- 禁止"点击后无任何反馈"：无反馈即视为未接线。

## 6. 危险操作确认

- 唯一入口：`openConfirmModal({ title, body, danger, onConfirm })`；**禁止新增原生 `confirm()`**
  （现存 39 处逐步迁移，触达即改）。
- 删除、清空、覆盖导入、断开集成、退出登录必须二次确认；确认按钮文案用动词（"删除"），不用"确定"。

## 7. i18n

- 新增文案必须同时加 `zh`/`en` 两个键；禁止只写中文默认值。
- JS 中的 `t(key, "中文兜底")` 允许保留，但 key 必须真实存在；硬编码中文只允许在注释与示例里。
- 用户数据、错误原文不进翻译层。

## 8. 可访问性

- 所有交互控件必须有无障碍名（文本或 `aria-label`）；纯图标按钮必须有 `aria-label`。
- 禁止正 `tabindex`；焦点样式统一 `:focus-visible`，不得 `outline:none` 后不补。
- 文本对比度：正文 ≥4.5:1，次级文本 ≥3:1（9–11px 文本按正文要求）。

## 9. 提交前检查清单

1. 新增颜色/间距是否走了令牌？2. 是否引入新断点？3. 按钮高度是否在三档内？
4. 异步是否有 busy 态？5. 空/错状态是否可见？6. 危险操作是否走确认组件？
7. 新增文案是否双语？8. 新浮层是否有 Esc + 焦点陷阱？
