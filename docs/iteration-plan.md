## v3.7.114 · 安全告知项（小批）

**目标**：两项「默认宽松」的安全面，用最低成本把「不知道」变成「知道」。

- **③ corsOrigin**：`cfg.corsOrigin === "*"` 时启动打 WARN（与占位 JWT 密钥同款显式警示口径），
  README 状态表与该配置项补一句「默认 `*` 是为开箱即通；生产应收紧」。
  不做：不收紧默认值（会把开箱即通变成开箱报错，用户 10-11 已认可此判断）。
- **② refresh token/数据文件**：数据文件写入时 `chmod 0600`（目录 0700）；
  README 明示「`cfg.dataFile` 即凭证文件——内有 refresh token 与全部用户数据」；
  状态表把「明文落盘」从待设计改为「有边界、有告知」。
  不做：不做口令派生/KMS（那是独立课题，攻击者拿到文件 ≈ 拿到整机，性价比不成立）。

**验收标准**：`node scripts/release.mjs` bump 后 build:check 过；新增 `server/verify/security-check.cjs`
两条——① corsOrigin 为 `*` 的实例启动输出含 WARN 行、非 `*` 时无该行（**反向断言是防回归的那半**：
若把 WARN 写成无条件打印，正向断言照样绿）；② 数据文件创建后权限 ≤0600（Windows 上跳过权限断言但
记录——本机 NTFS 语义不同，CI ubuntu 上真断言）。
门禁链 + 单测 + e2e + CI + 线上指纹。

> **交付记录（2026-10-11）**：security-check 22→25/25（③ 两条用例 + 端口动态化改造的连带发现）；
> 七脚本合计 176。**计划外附带项**：本批实测 4571/4572/4574/4575/4576/4577 相继被本机占用
> （Windows Hyper-V 保留段），七个验证脚本 + oauth-check 假 provider 端口全部改 `freePort()` 动态分配
> ——「端口被占」与「实现坏了」表现不同，属必然复发的假红源，一并根治。

## v3.7.115 · 检索降级可见性（小~中批）

**目标**：让「语义检索悄悄退化成词法」这件事对用户可见（当前静默，用户以为 AI 记得）。

- 诊断行/同步面板新增一行「语义检索」：`向量可用 / 词法降级（原因：embedding 通道不可用 /
  IndexedB 未就绪 / 未配置）」，状态从既有降级路径读取，不新增探测请求。
- 用户手册同步：排障表「语义搜索找不到内容」一行指向新诊断。
- 不做：不做自动修复（换通道/重建索引仍走现有入口）。

**验收标准**：`tests/` 新增用例覆盖三种状态渲染（可用/通道不可用/IDB 未就绪）；
诊断行内容与 `ragVectorSearch`/`memEnsureVectors` 的既有降级标志一致（不自己造第二套状态）。

## v3.7.116 · 断点续跑（大批 · 天花板之首）

**目标**：自主计划（`>` 评审链）执行中途刷新/崩溃后，**下次进入可原地续跑**。

- `pendingAgentPlan`（评审态）与执行进度（第几步/已完成步骤摘要/剩余计划）**落盘**
  （新键 `wb_agent_agent_run`，带上一次运行的 replay 摘要，容量上限 1 份，新运行覆盖旧）。
- 刷新恢复：命令面板/对话框提示「有一个未完成的执行：第 N/共 M 步 —— 继续 / 放弃」；
  继续从下一步开始，不重跑已完成步骤（以数据现状为准，不盲信缓存摘要——与 mv 冲突同口径：
  摘要只用于提示，实际状态以存储为准）。
- 编号与取消沿用现有 signal 机制；执行完/用户放弃即清档。
- 不做：不做跨设备续跑（那是云同步 + 执行状态合并的大课题，明确拒绝——
  「本机执行态上云」会引入比现在更危险的语义）。

**验收标准**：jsdom 用例（模拟运行中 evaluate 清档前后、刷新再进入）覆盖
续跑/放弃两条路径 + 摘要与真实数据不一致时不重跑已完成的步骤；`_probe/` 真机探针一轮。

## v3.7.117 · 两套拆解机制合一（中批）

**目标**：消灭「两套互不相认的多步机制」。

- `>` 自主计划的评审确认后，**写入与 `plan` 工具链同一目标存储**（`wb_agent_goals`），
  步骤带来源标记（`src:"palette"`），使「继续执行」话术（agentContextPrompt）
  对两套机制都生效；旧的目标数据兼容读取。
- 命令面板入口保留（它评审体验更好），但状态只有一份。
- 不做：不改 `plan` 工具的 schema（客户端与模型侧契约不动）。

**验收标准**：旧 goals 数据升级用例（无 src 字段）；`>` 计划确认后刷新，
  下一轮对话注入同样的「请继续第 N 步」；两套入口互不覆盖（同一目标）。

## v3.7.118 · 上下文滚动摘要（大批）

**目标**：长会话的 token 成本从「随轮数线性涨」转为有界。

- 超阈值（沿用 `cfg.ctxBudgetTokens` 口径或新设 `cfg.histSummaryAfter`）时，
  对最旧的对话段生成一次摘要（一次额外请求，失败则维持现状截断——降级路径优先于新功能），
  摘要 + 最近 N 条原样进入 messages。
- 摘要可被用户查看/清除（新诊断行），不静默改历史。
- 不做：不做向量化长期记忆（那是记忆系统重构，单独课题）。

**验收标准**：用例覆盖——阈值内零额外请求（行为不变）；超阈值确实少发 token
  （用请求体大小断言）；摘要请求失败时回退既有截断且不报错。

## 风险与回退

- 116/118 都动 `ai-retry.js`/`ai-tools.js` 的循环与存储——两文件是并发会话也可能触碰的
  共享面，动工前必 `git status` + fetch，提交只列显式路径。
- 每一个大批都遵循「先造可复现用例再改实现」：断点续跑先写 jsdom 刷新场景用例（当前必红），
  摘要先写 token 计数断言（当前必红），红了再修。
- 任一批 CI 红且根因在本次改动：就地修 + 复跑；根因是环境抖动（本机/runner 瞬时）：
  按 audit 台账既有口径记「同 commit 重跑」再判，不靠加超时掩盖。

## 已知 CI 形态（v3.7.114 实证，后续批次直接对照）

**「全过只红一行」的 Unhandled Rejection = 启动 teardown 竞态**，不是用例失败：
`startup()` 是 `async`，`applyTheme`/`setupSideToggle` 等排在 `await initCrypto()`
之后；测试在这个 await 期间关窗，恢复执行时 `document` 已销毁 → TypeError。
判据：Test Files 143 passed + Tests 1636 passed，红的是 Unhandled 块而非 `✕/×` 用例。
**修的是根因不是单点**（v3.7.113 修了 applyTheme；v3.7.114 顺藤摸到壳层 `$` 助手
一次性修掉整族）。本机复现不出该时序窗口（CI 专属），**判据以 CI 为准**——
本机全绿不能作为该形态已修的证明，必须等 CI 复跑。
同理已根治的还有「端口被占」（七个验证脚本全动态化，见 v3.7.114 交付记录）。
